## Introduction to Backend Development
Some language to be aware of: mostly we only hear frontend/backend, but there is a different term used, Static vs Dynamic 
Static web pages (not applications) vs Dynamic Web Applications

Dynamic applications allow the application to be customized to the user, not the same page for anyone who goes to that application 

When the user makes a request, the server can run a program that can interact with a database or files. It can generate a custom response for the user and return that. 

Why backend development exists 
- Data persistence
- User Management
- Security
- Shared Data
- Business Logic: JavaScript might have to do frivolous little things and also super important tasks. Business logic is the essential stuff. We implement the important stuff on the backend also, so people can't just mess with things in the front-end code that's available to everyone.

Side note: Frameworks are not libraries!

In frameworks, you will hear about design tension between convention and configuration 
- boilerplate code that's accepted, add a bunch of more conventional defaults
- configuration is more customized and has fewer defaults, you're supposed to use 

ORM = Object Relational Mapping tool
ORM allows us to coordinate across languages in different databases. Often, a database uses a domain-specific language that's really good for that database. But you're working in Python and need to coordinate with them. Jenga will write the request you send to a database into an SQL format for you using their ORM tool. Though you can do this yourself.
